## 这个节点说明什么

**借鉴架构；观察成熟度。** 不能把后来的功能丰富误读成从单一聊天产品重写而来：此时架构已经以 Cordis 插件组合 loop、模型、工具、Session、压缩和界面。日志派生上下文、并行工具调度、规划和长目标也已存在。当前研究只确认这些能力“至少在 rc.7 已有”，不推定首次实现日期。[当时架构][S1]、[循环源码][S2]

## 六维快照

| 维度 | 当时证据与边界 |
|---|---|
| 产品、交互、部署 | 官方架构已描述 Web 与 Headless 组合；Python SDK 通过子进程 stdio JSON-RPC 使用随包 runtime。不能把今天全部 profile 名称或 Desktop 分发方式写回该版本。[架构][S1]、[Python SDK][S3] |
| Loop、规划、并行、恢复 | 源码已有并行安全工具池与独占屏障，默认并发 10；`agentLoop.create()` 当时是同步接口。Plan 是软引导，Goal 用同一会话继续工作且恢复后需重新授权续行。[调度][S2]、[循环 API][S4]、[Plan][S5]、[Goal][S6] |
| Context 与 memory | `SESSION_FORMAT_VERSION=0`，仍有持久 `assistant/chunk`；基础压缩含工具结果修剪、摘要及配对边界。外部记忆已经是默认关闭的 MCP 参考组合，并非内置长期事实库。[类型][S7]、[压缩][S8]、[记忆示例][S9] |
| 插件、Skills、模型、集成 | release 增加插件自行注册设置卡片，外部 Codex／Claude Code 任务进入 Job Panel，MCP／ACP 图片支持持久化。Skills 文件扫描包已存在；这些是具体接入点，不证明完整企业 IM 集成。[R]、[Skills][S10] |
| 身份、审批、沙箱、审计 | 基础组合已有 `workspace-write` 与 `ask`，Plan 与权限策略分离。当时 Linux bwrap 参数没有后续加入的 PID namespace 隔离；下文的后续修复不能被忽略。[基础配置][S11]、[bwrap 参数][S12] |
| 日志、异常、升级、成本 | release 自报修复大历史分页和 max-token 截断后无法续聊；基础配置中 OTel 遥测关闭。摘要已有额外模型请求，Goal round 限制不等于总费用上限。这里的 OTel 状态不能推出后来 Session Log 通道也关闭。[R]、[配置][S11]、[压缩][S8] |

## 相邻阶段揭示的迁移与风险

此时 JSONL 之外还有可选 SQLite 持久化 provider。[SQLite 说明][S13] 后续 [rc.8](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.0-rc.8) 宣布 SQLite 格式不兼容变化，[v0.1.2-alpha.3](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.2-alpha.3) 则移除该后端，保留旧数据并提示通过旧版本导出。**推断：**早期迁移成本包含存储后端生命周期，不能只检查应用版本号。

安全上，[v0.1.1-rc.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.1-rc.1) 明确报告修复 bwrap 经 `/proc/<pid>/root` 绕过限制的问题；核对该 tag 的参数已增加 `--unshare-pid`。[修复后源码][S14] 这是官方披露的历史修复，不是本项目复现，也不能据此声称当前版本仍存在该问题。rc.7 根目录没有后来的 SAFETY 文件，不代表当时安全。

企业平台可立即**借鉴**日志／投影和调度分层；若为理解历史行为保留旧版本，应只做源码研究。**未知：**这些接口在真实任务、崩溃、跨平台与非可信输入下的可靠性，本项目没有运行数据。
