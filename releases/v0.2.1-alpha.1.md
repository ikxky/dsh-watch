## 实质变化

**观察插件生态；验证扩展兼容。** 这一版增强插件创建、安装反馈与诊断，同时删除旧的运行时 invariant 扩展入口。实验性 Claude Code Mods 用于检验 API 映射可行性，官方没有承诺完整可用兼容；不应把出现兼容层等同无修改迁移。[R]、[当时兼容层契约][S1]

## 六维增量

| 维度 | 相对 v0.2.0-rc.2 的主要变化 |
|---|---|
| 产品、交互、部署 | `--public-url` 支持外部公告 URL 及反向代理路径前缀；Desktop 默认由系统分配端口。它们不是原生 TLS 的引入证明，TLS 等后续变化见 alpha.2。[R] |
| Loop、规划、并行、恢复 | 官方修复 Goal 停止→恢复→再停止后队列滞留；工具准备信息可提前展示。仍需区分 UI 提前出现与真实执行完成。[R] |
| Context 与 memory | Session 格式仍为4；开发者组合提供原始日志与聊天定位。可观察历史不等于新的长期记忆能力。[格式常量][S2]、[R] |
| 插件、Skills、MCP、模型、SDK | 新增实验性 Mods 桥接及“让 Agent 创建插件”入口；子路径插件元数据改从导出读取；HMR 改善依赖映射，但替换已安装包仍需重启。[R]、[S1] |
| 身份、审批、沙箱、审计 | 本次定向阅读未确认新的企业身份或隔离保证；源码中 Team 仍依赖 mailbox。不能提前赋予下一版直接 inbox 的交付语义。[Team 源码][S3] |
| 日志、异常、升级、成本 | 移除运行时 invariant 插件／`./invariant` 导出，输入区统计拆成 activity、usage；原有诊断扩展需迁移。新增开发者工具不等于获得完整合规审计或费用预算。[导出前后][S4]、[S5]、[R] |

## 配置与兼容性边界

**源码核实：**Web 组合直接挂载 schedule 和其 UI；相对上一版可选 bundle，这是实际的组合变化。官方说明提醒工具向标准、创造和 PTC 模式提供，极简与子代理不提供，旧实验组合选择清理但保留任务。[Web 配置][S6]、[上一版可选组合][S7]、[R] **推断：**只看包是否安装无法回答模型是否能调用工具，企业接入要记录 profile、模式和工具暴露三层。

**源码核实：**AgentLoop 包的 `./invariant` export 与相关依赖在此版移除。[旧 package][S4]、[新 package][S5] 这证明扩展接线有破坏变化，不证明所有内部校验或测试被删除；不能把诊断入口删除直接写成安全回退。

**观察／验证：**现有插件的注册 ID、子路径元数据、依赖映射和重启要求是迁移检查重点。Mods 的未实现事件／成员需要按官方差异表逐项判断。到 [alpha.2](v0.2.1-alpha.2.md)，SDK 又增加等待子树工作结束的接口，Team 投递机制也变化；它们应作为下一次增量，不归到本版本。**未知：**兼容插件的真实成功率、HMR 长期稳定性及诊断完整性，没有本项目实测。

## 插件专项补充 · 2026-10-13

Web 默认挂载 schedule／ui-schedule，旧可选 Schedule 退出清单，Inspector 进入，清单仍为四项。插件子路径元数据、统计注册 ID 和 invariant 导出变化必须按接口记录。四个 npm 归档所查 YAML 与 tag 一致；不能由版本号变化推断每个插件都改变行为。
