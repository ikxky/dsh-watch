## 实质变化

**借鉴持久化契约；验证迁移；观察性能回退。** 关键增量是 `SessionHandle` 生命周期、单 Session 写持有者及异步创建；同时日志进入格式 v2，将 assistant 流收敛为 attempt settlement。它强化了持久记录边界，也改变插件 API 和自定义日志消费者。源码确认 `create()` 为 async、持久化通过 create/open 返回 handle，以及 JSONL provider 的跨进程锁。[循环入口][S1]、[持久化实现][S2]

## 迁移判断与后续证据

**推断：**升级至少需要检查三个消费者：直接调用 AgentLoop 的插件、持有 Session 的后台服务、解析 assistant 流的日志／审计工具。保留旧 generation 有利于追溯，但不等于新版会话可交给旧 runtime 降级继续写，也不证明中断时的瞬态输出都已结算。

官方 [v0.1.3-alpha.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.3-alpha.2) 随后报告长历史性能、内存和进程清理方面的改进。应将它记作针对回退的后续修复证据；不能把 alpha.1 的已知问题写成长期未修复，更不能据 release 自报推导所有性能问题消失。

另一个证据细节：本 tag 的抽象持久化 README 仍留有逻辑格式 v1 字样，而代码常量和 release 都指向 v2。研究采用源码常量并列明差异，不用滚动文档修补历史。[抽象层文档][S7]、[类型][S3] **未知：**真实迁移成功率、锁在网络文件系统的行为、崩溃与重开时延，均未测试。
