# Superagent 持续 Router 与业务协作 PoC

**状态：实施计划与合成测试语料已准备；未安装、部署或运行 Superagent，未连接真实办公渠道，未形成性能或采用结论。**

本专项研究：多个办公渠道持续送来文本、语音、图片、视频和文件时，Superagent 能否持续响应、区分并行事项、处理晚到材料与需求变更，并让后台 Worker 完成可核验的工作。

范围固定为 [DeepSeek Superagent 原型 `8c32a9d`](https://github.com/deepseek-ai/dsh-superagent-prototype/tree/8c32a9dc5d72c033816c6a8110b37f40cf94fba4)。不继续扩大候选框架，不把新增适配层的效果记成官方原型现有能力。官方定位是单 GitHub 仓库的编码研究原型，已有 GitHub 和飞书 Source；Slack、企业微信、普通微信群与通用办公业务是本专项要验证的适配目标。

## 两条工作线

- **A：混合样本业务评测。** 固定多来源、多批次和多模态语料，直接测试事件进入后的事项识别、事实维护、授权、续接、恢复和成果核验。原始媒体组与预解析文本组配对，分别定位媒体理解和业务处理问题。
- **B：真实输入适配。** 单独验证 Slack、企业微信和 WeFlow 类微信路径能取得哪些消息与附件、增量同步是否完整、身份和回复关系是否可靠。输出统一事件，再进入 A 使用的同一处理路径。B 不阻塞 A 的准备和离线评测。
- **最后联调。** 在另行确认测试账号、群、读取范围和发送权限后，用测试会话复现同一业务案例，确认真实输入与回放输入差异。

## 保持三个实验边界

| 实验标签 | 含义 | 可以据此声称什么 |
|---|---|---|
| B0 官方原样 | 固定官方源码、提示词与支持的配置，记录真实安装版本 | 原型原样的可用性和明确暴露的限制 |
| B1 回放适配 | 官方核心不改，独立 Replay Source / harness；挂接方式先验证 | 原型控制机制与样本组合的效果；适配部分另算 |
| B2 目标扩展 | 通用业务规则、多模态解析服务、事实版本、动作前授权复核等 | 目标设计的效果，不能反推官方原型已支持 |

B0 不能表达某个办公场景时记“能力未覆盖/未运行”，不先改原型再称原样测试通过。B1 不能无源码修改挂接时，先报告接口阻碍，再决定是否进入独立 fork 的 B2；本次不做该改造。已确认完整 Runtime 的 setup 需要测试 GitHub 仓库和具有 push 权限的 agent 身份；未授权这些条件前，只能做离线 core harness，不能宣称完整原样 Runtime 已跑通。

## 本次交付与安全边界

- 文档和语料使用完全虚构的人、群、报价与业务，不含真实群记录、登录态、密钥、手机号或商业资料。
- 真实媒体是程序生成的合成素材，用来验证实际文件输入链路，不是真实客户数据。语料内的业务指令只作用于隔离测试沙箱。
- 评分答案在独立目录，**在公开仓库中可见**；“隔离”指运行时不能交给被测系统，不意味着保密。正式盲测另做未公开、未训练的留出集。
- 已有生成、校验脚本仅处理本地测试材料；它们不是完成的 Superagent 注入器，也不连接渠道或发送消息。
- 后续安装、模型调用、收费资源、真实数据接入、对外发送和持久授权仍需具体确认。本次授权仅完成专项文档与语料落盘。
